# 工作流细则（阶段一 / 阶段二）

本文件承接 `SKILL.md` 迁出的执行细则。主流程只有一条（见 `SKILL.md` 第 2 节），这里是每一步的展开、
派发协议、验收口径与返修回路；遇到报错或需要重跑时按此处置。

> 听音通道的调用与分页契约、依赖与凭证见 [`runtime.md`](runtime.md)；
> CLI 全表与参数见 [`cli-cookbook.md`](cli-cookbook.md)；产物规范与目录树见 [`delivery_matrix.md`](delivery_matrix.md)。

## 1. 阶段一：块级转录 → 模块长文

### 1.1 两类任务书

| 任务书 | 位置 | 交给谁 | 内含 |
| :--- | :--- | :--- | :--- |
| **块级转录任务书** | `subtitles/BLK01_P01-P07_转录任务书.md` | **转录角色** | 块音频绝对路径、块内每集起止时间表、逐字稿目标路径、纯文本转录要求 |
| **模块长文任务书** | `articles/模块XX_<块标题>_TASK.md` | 写作角色（子智能体） | 本块逐字稿路径（**唯一事实来源**）、块覆盖分集清单、目标长文路径、所选类型的撰写提示词 |

块级逐字稿有两个合法来源——听音转录，或 B 站中文字幕；取不到字幕的块留给听音兜底。
模块长文任务书**只给逐字稿、不夹带任何音频切片清单**：写作侧只吃文本，音频留在块里、由转录角色消费。
任务书第 1 节写明「本块逐字稿（唯一事实来源）」，并给出前置条件：**逐字稿缺失就立即停止并回报**，不得编造。写作侧不接收音频输入。

### 1.2 装箱规则（块边界）

- 块由 `pipeline` **只看课程元数据**（集号 + 时长）自动装箱，**规划阶段不下载、不读取任何音频**：
  连续几集合并成 **40–60 分钟**的块
  （目标时长 `--block-minutes` / `BVB_AUDIO_BLOCK_MINUTES`，默认 50；单块硬上限
  `BVB_AUDIO_ONESHOT_LIMIT_MINUTES`，默认 75——超过取音侧一次性就绪阈值会被自动分卷，调用次数反而回升）。
  两条规则：**小集合并**（多集凑到带内，并在可行切法里取块间最均衡的一种）、
  **超长集劈上下**（单集 > 60 分钟时取最小段数均分，标签写成 `P12上` / `P12下`，绝不把一集劈进同一块两次）。
- **块就是知识模块**：块标题由块内分集名**语义组合**而来（不是机械截断，也不是另拟），随计划保存在工作区
  根目录 `block_plan.json`；只有缺字幕块才会有物理音频，落在 `audio/blocks/BLK01_<标题>(P01-P07).m4a`。
  想换标题就改根目录 `block_titles.json`
  （`{"01": "HTML入门、常用标签与表单", …}`）后重跑 `pipeline`，
  幂等改名并刷新全部引用；标题缺失时退化为「首集标题 + 集号区间」，**绝不空名**。
- `block_plan.json` 是块编号、块边界与交付物命名的**唯一事实源**：它只保存逻辑信息（`units` / `segments` /
  `span` / 时长），**不保存任何音频路径**；物理路径由 `AudioMaterializer` 按已锁定的计划推导。
- **计划落盘即锁定，只允许按新分集追加**：连载课程新增分集时只规划新分集，旧块与旧边界原样保留；
  旧分集参数变了、或者显式改了 `--block-minutes`，直接报错要求换新的 `--task` 工作区，绝不隐式重排
  （不传 `--block-minutes` 时沿用已锁定的 limits）。
  注意 `--force` 与计划是**两条独立的通路**：它只重取音频、逐字稿与任务书；而 `BlockPlan.ensure`
  每次调用都会执行（不受 force 控制），所以"跑了 pipeline 计划就会被动过"是正常的（只为新分集追加）。
  要**排除**某些分集，做法是保留 `source.parts` 全长、只裁 `blocks`——手工裁短 `source.parts`
  会被 digest 自校验拒绝，那正是"排除的集被当新增重新规划成块"的成因。

### 1.3 转录角色（取音唯一发生处）

> **字幕阶段**：`pipeline` 在 B 站且有登录态时自动优先抓取中文字幕，且**只采用通过内容核验的字幕**。接受判据有三条：① **URL 身份锚点**（最强）：B 站 AI 字幕文件名内嵌 `aid+cid`（`/prod/<aid><cid><hash>`），与响应回显的 `aid`/`cid` 前缀对不上即判串台。实测 21 个样本零误判（8 次判等全是本集内容、13 次判不等全是别家内容），**且能拦住时长贴合（覆盖率 98.3%）的错件——那是两条时长判据都会放行、只有它能拦的形态**。人工 CC 不走 `/prod/` 路径、拿不到 `aid` 时该判据不适用，交给时间轴判据。 ② 时长覆盖下界：末条 ≥ 90% 分集时长。③ 时长越界上界：ai 轨末条 > 110% 即判串台。原先叠的标题术语身份判据因实测假杀率 90%（`CN_SUBWINDOW_WIDTH=3` 把「哈夫曼树」切成 `夫曼树`，而 AI 字幕写「哈弗曼」）**已整条删除**。
> **每次取回都是一次独立抽签**：实测单次抽中正确轨约 28%，坏抽签里 URL 失配约 45%、空 URL 约 24%。故重取轮数**上限 10 轮**（`BVB_SUBTITLE_ATTEMPTS` 只能调低），把单集覆盖率从 3 轮的 62.7% 提到 96.3%（最坏退避 67.5 秒）。「零中文轨」同样按坏抽签处理并可重试，但只给 3 轮子预算——那是确认性重试，不该让整门课都没字幕的课程白等满额退避。
> **按集兜底（不再整块一刀切）**：取到字幕的集照常拼装，缺的集只记账。可用部分落**暂存稿** `BLKxx_<span>_字幕部分稿.md` + 同名 `.json`（记 `ready_pages` / `missing_pages`）；转录任务书**只覆盖缺的那几集**，音频指向分集音频、目标指向 `BLKxx_Pyy_补录逐字稿.md`；补录齐备后合并成最终 `BLKxx_<span>_逐字稿.md`，抬头逐集声明来源、`transcript_source` 判 `"mixed"`。暂存名刻意不含 `_逐字稿.md` 后缀，因此不会被「最终稿存在即整块完成」的判定误认。
> 排查口径：判不可用的分集在 `manifest.json` 的 `pipeline.subtitle.unavailable`；块级丢页因果链在 `pipeline.subtitle.missing`；逐集来源在 `pipeline.subtitle.page_sources`；被听音/混合稿保护而未覆盖的块在 `pipeline.subtitle.kept_audio`。

1. 取载荷：`python scripts/queue_tracker.py --next-transcribe --json`（默认并发 3 个任务；载荷含块音频、块内时间表、逐字稿目标路径）。
2. 读块级转录任务书，按其 2.1 节要求**原样**把「纯文本忠实转录」要求传进听音调用；通道选择与调用见
   [`runtime.md`](runtime.md) 第 2 节（优先 read_media，无 ext 时才 read_audio）。
3. 把整块正文写入 `subtitles/BLK01_P01-P07_逐字稿.md`。逐字稿**首行必须写来源抬头**
   `> 来源：**听音转录**——非平台字幕，由讲师原声转录`，且**无需标注任何时间戳**，专注保证讲授内容
   忠实度、技术术语、代码公式与推导脉络的完整性（**唯一事实来源**）。
   抬头不是装饰：下游据它判断「这份稿该不该被平台字幕覆盖」——听音稿质量高于字幕碎片，
   没有抬头就会被判成无来源，从而被 `--force` 降级覆盖（实测发生过，不可逆）。
4. 只回报一行：`BLK01 | 逐字稿路径 | 字节数 | 执行者`；**不回传正文**（回传会把主上下文重新撑满）。

> **通道不可用 ≠ 可以换工具**：`read_media` 上游返回 5xx 时，按 `runtime.md` §1.3 ⑥ 停下排查本机代理／加速器，
> 修好后重跑；**不得**改用本地语音识别模型（faster-whisper / whisper.cpp / Vosk 等）或任何第三方 ASR 顶替转录，
> 更不得为此下载模型权重——这类替代的精度低于通道 B，且会长时间占满本机 CPU。

### 1.4 写作角色（按块成文）

1. 主 Agent 取载荷：`python scripts/queue_tracker.py --next-module 5 --json --log-dispatch`
   ——只返回「块逐字稿已就绪且模块长文缺失」的块。
2. **一个块一个子智能体**，并发建议 5~6；**直接原样透传载荷中的 `dispatch_prompt`**，禁止自编或扩写提示词。
3. 子智能体读该块逐字稿（任务书第 1 节给了绝对路径），把这一整块讲的内容**写成一篇文章**
   （不是把几集拼在一起，也不逐集机械分小节）：按 H2 自拟标题、**不写序号**，载入所选风格提示词。
   - 逐字稿未就绪时**立即停止并回报**，不得凭块内集标题编造、也不得去别处找音频补听。
   - 讲师只在幻灯片上展示、音频里没有逐字念出的代码或表格**不要替他补写**。
4. 落盘 `articles/模块XX_<块标题>_精读长文.md`（≥ 1000 字节方视为完成）；只回报一行：`BLK03 | 文件路径 | 字节数 | 执行者`。

### 1.5 派发协议与并发

| 环节 | 做法 |
| :--- | :--- |
| 取载荷 | 派发前**必须**跑工具取载荷，**禁止手抄路径**（手抄会让同一个块被派两遍，白烧几十万 token） |
| 派发粒度 | 一个块（= 一个知识模块）一个子智能体，一篇模块长文；块已是 40–60 分钟粒度，不再二次打包 |
| 并发 | 建议 5~6（`suggest_workers` 给出建议值；不得超过宿主并发上限） |
| 派发节奏 | 默认**按批**（取 N → 派 N → 全落盘后再取下一批）；需要「完成一个、立即补一个」时用滚动补位：取载荷加 `--claim`（见下） |
| 子智能体输入 | 直接原样透传载荷中的 `dispatch_prompt`；主 Agent **不代读、不代听** |
| 子智能体输出 | 只写目标长文，**不回传正文** |
| 回报格式 | 固定一行：`BLK03 \| 文件路径 \| 字节数 \| 执行者` |
| 验收 | `queue_tracker.py --summary` 看 `STAGE1_DONE`；`--next-module N` / `--next-transcribe N` 复核剩余待办 |
| 返修 | 质检不达标时，把「文件:行号:原文」贴回该块子智能体重派，最多 2 轮；仍不达标由主 Agent 亲自返修该块 |

> **派发台账（观察性证据）**：加 `--log-dispatch` 会把本次建议的块追加写入 `<task>/.dispatch_log.jsonl`。
> 它记录的是「工具建议派发了哪些块」，**不等于**「谁真的写了」——执行者身份无法在工具层验证；
> 台账用于事后复盘派发节奏（例如某工作区从未出现台账，说明阶段一没有走派发流程）。

> **滚动补位（`--claim`，可选）**：默认按批派发时，上一批没全落盘就不该再取载荷；需要「完成一个、
> 立即补一个」时，取载荷加 `--claim`：工具把本次取出的块登记为**在途认领**
> （`<task>/.dispatch_claims.json`），此后每次取载荷都自动排除「已认领且成品未落盘」的块，
> 因此在任何一个子智能体完成时重跑同一条取载荷命令，得到的就是空出的补位槽，而不是在途块的重派。
> 认领有粘性：登记过一次后，后续取载荷**不传** `--claim` 也照样排除在途块，直到文件被清空。
>
> - **自动释放**：成品落盘即释放，无需手工对账。转录认领的释放条件是**整块**逐字稿
>   （不是补录稿/部分稿），所以按集补录期间不会被重复派发；模块长文认领看长文落盘，笔记认领看成品落盘。
> - **失败重派**：`--release BLK03`（或 `--release 笔记01`、`--release all`）释放后再取载荷；
>   忘了释放也不会永久堵块——超过 `BVB_CLAIM_TTL_MINUTES`（默认 360 分钟，`--claim-ttl-minutes` 可覆盖）
>   的认领自动过期并打印。
> - **断点恢复**：`--claims` 列出在途清单（编号、类型、认领时间、目标路径）；工作区删掉认领文件即回到
>   无状态按批模式。三种角色（转录 / 写作 / 笔记）共用同一套机制，无状态排除也可用 `--exclude BLK01` 手工叠加。

### 1.6 阶段验收

```bash
python scripts/queue_tracker.py --next-transcribe --json          # 转录侧：待转录的块（默认并发 3 个任务）
python scripts/queue_tracker.py --next-module 5 --json --log-dispatch  # 写作侧：待写长文的块
python scripts/queue_tracker.py --claims                         # 在途认领清单（滚动补位断点恢复/排查）
python scripts/queue_tracker.py --summary                        # 单行状态：STAGE1_DONE + 块级进度
python scripts/queue_tracker.py --pattern "<目录名关键字>"        # 多课程并存时指定工作区
python src/cli.py check --stage1 --strict                        # 长文确实基于本块逐字稿
```

- `STAGE1_DONE=1`（**全部块的模块长文均 ≥ 1000 字节**）是**硬前提**；集号只作「块覆盖了哪些集」的派生视图。
- 块级转录进度看 `--summary` 的 `BLOCKS/BLOCKS_TRANSCRIBED/BLOCKS_PENDING` 三项，**就绪口径是块**
  （`BLKxx_*_逐字稿.md` 存在即算就绪）。
- 没有 `block_plan.json` 的工作区不做阶段一判定（`stage1_unit=none`），界面会提示先跑 `pipeline` 建立计划。

### 1.7 门禁 vs 纪律（边界声明）

| 项 | 性质 | 工具层能否校验 |
| :--- | :--- | :--- |
| 模块长文 ≥ 1000 字节、任务书存在、块清单/逐字稿齐备 | **机器门禁** | ✅ |
| 长文风格命中已提供预设（`learning` / `legacy`） | **机器门禁** | ✅ 未命中即退出码 4 终止 |
| 模块长文是否基于本块逐字稿 | **机器门禁（启发式）** | ✅ `check --stage1`：一块一验，**双层实体覆盖率**——① 英文标识符与多位数字（讲师念出的术语/公式/表名）② 中文技术术语骨架（连续汉字段按停用字切出的完整术语，繁简已归一）。**任一层达到下限即放行**：忠实长文常把 `sno`/`cno` 改写成「学号/课程号」，英文层因此偏低，中文层正是替它兜底的那一层；两层同时低才是脱稿文。口水词（`ppt`/`sorry`/「这个」）不进分母，避免逼写作者凑词；无逐字稿的块不参与判定 |
| 谁写的、转录是否忠于原声、转录/写作角色数量与并发 | **纪律条款** | ❌ 只能靠 `.dispatch_log.jsonl` 观察委托节奏 |

## 2. 阶段二：块 → 笔记归并 ＋ 教材整编

阶段二由工具链与 Agent 交替推进，**只有一趟语义规划**：把**块**归并成若干篇笔记。
**模块层不需要规划**——块就是知识模块，教材照**块序整编块长文**即可。

```bash
python src/cli.py cluster-notes "<链接或路径>"      # 块 → 笔记归并 + 导出笔记任务书
python src/cli.py cluster-articles "<链接或路径>"   # 按块序整编成册
```

### 2.1 笔记归并（`note_plan.json`）

工具读各块的**块标题**与**模块长文 H1**，导出归并任务书：

- **任务书**：`<产物根>/<task>/note_plan_TASK.md`（课程级唯一，**永不回收**）
- **目标文件**：`<产物根>/<task>/note_plan.json`，形如
  `[{"note_id": 1, "note_title": "进程管理与调度体系", "blocks": [3, 4, 5], "core_theme": "…"}]`
- **归并依据**：块标题（装箱时的先验语义组合）+ 模块长文 H1（Agent 读完语料后写的主题，如「变量与作用域」）。
  只照块标题归并容易归错。
- **约束**：`blocks` **恰好覆盖全部块各一次**（不得遗漏、不得重复）；集号由 `blocks` 自动推导，不需要 Agent 填写。
- **一篇笔记可以跨多个块**（这是常态）：一个块整体进一篇笔记、不拆开，但讲同一套体系、同一条技术栈、
  同一条学习路线的若干块**必须合并**。宗旨是**宁可少而厚，不要多而碎**。归并**不给篇数配额**。

> **缺归并不停机**：工具会导出归并任务书、按「一块一篇」兜底粒度继续把流程走完，命令**始终正常退出**；
> 盘上的 `note_plan.json` **一个字节都不会被兜底结果覆盖**，Agent 补齐归并后重跑即自动替换。
> 凡是「漏认领／重复认领／引用不存在的块」的归并都当场抢救（先到先得、孤块补兜底笔记）。

> **为什么删掉了「第一趟模块规划」**：旧链路让 Agent 读块内每集长文的 H1 再划一遍模块（`topic_plan.json`，供教材）。
> 块级装箱落地后这件事成了重复劳动——块边界本身就是语义边界；两套边界一旦不一致，同一条语料会被切成两种粒度。
> 现在教材**直接按块序整编块长文**，`topic_plan.json` / `topic_plan_TASK.md` 不再产生。

### 2.2 笔记任务书与派发（`notes/笔记XX_*_TASK.md`）

归并就绪后重跑，工具逐篇校验**该篇涵盖各块的模块长文是否齐备**，齐备即导出笔记任务书：

- **目标文件**：`<产物根>/<task>/notes/笔记XX_<主题>_笔记.md`
- **语料**：该篇涵盖各块 `articles/模块XX_*_精读长文.md`（任务书中列出**路径清单 + 字节数**）
- 抬头写明「涵盖块」与「涵盖分集」，让子智能体清楚这是**跨块聚合**笔记，而不是「一个块一篇」。

Agent 需按任务书内的专属提示词撰写，逐条落实其中的六节：**笔记信息与唯一事实来源**、**工作流程与目标形态**、
**内容要求**、**结构要求**、**条目骨架**、**排版**；笔记只有这一种风格，无需再指定风格。
若某篇尚有块没有模块长文，该篇会被跳过并打印待办，其余照常推进。

派发推荐做法（**一篇笔记一个子智能体**）：

| 环节 | 做法 |
| :--- | :--- |
| 取载荷 | `python scripts/queue_tracker.py --next-note N --json`，载荷内自带预制 `dispatch_prompt` |
| 输入 | 直接原样透传 `dispatch_prompt`；子智能体按清单**逐篇整篇读完**该篇涵盖的全部模块长文（主 Agent 不代读） |
| 输出 | 只写 `notes/笔记XX_*_笔记.md`，**不回传正文**；回报固定一行：`笔记XX \| 文件路径 \| 字节数 \| 覆盖块` |
| 并发 | 建议 5~6，笔记多时分批派发 |
| 返修 | 质检不达标时，把「文件:行号:原文」贴给该篇子智能体重派，最多 2 轮；仍不达标由主 Agent 亲自返修 |

> 笔记的唯一事实来源是**模块长文**（不是逐字稿）。旧链路的「知识元（kernel）可选索引」已随逐集链路整体删除，
> `--kernel-index` 与 `subtitles/kernels/` 不再存在。
>
> **笔记产物命名**：规范名是 `笔记XX_<主题>_笔记.md`；成品后缀若不是规范名，仍按 `笔记XX_*` 前缀回退认出。
> 旧命名 `模块XX_*` 不再兼容（它属于「一模块一篇」时代）。
>
> **被取代的任务书会自动作废**：归并粒度变了之后，上一轮留下的、编号或主题已对不上的
> `笔记XX_*_TASK.md` 会被自动清掉并打印数量。已有成品落盘的任务书不动（那是交付记录，交给 `cleanup`）；
> 用 `--block-id` / `--start-block` / `--end-block` 分批派发时也不会清。

### 2.3 教材整编（`textbook_plan.json` / 兜底）

**册 = 书、章 = 块**，分册按实际内容（不是按体量硬切）：

1. **Agent 规划（首选）**：读 `textbook_plan_TASK.md`（列出各块的覆盖分集、时长、块标题与长文主题），
   把块按知识体系分成若干册、给每册起一个**能看出内容的名字**，写入 `textbook_plan.json`
   （形如 `[{"volume_id": 1, "volume_title": "SQL 标准语言：数据定义、查询与更新", "blocks": [9,10,11,12]}]`）。
   校验口径：块恰好被认领一次、册名不得是「第一部分」这类空名、`volume_id`（给了就必须是从 1 开始的唯一整数）；
   不合法当场抢救（孤块补兜底册），盘上的规划文件一个字节都不改。
   **册序以数组位置为准**：`volume_id` 只是标注，别靠它表达顺序（写成乱序不会被采用）。
2. **内容结构兜底（无规划时）**：按 `parts.json` 的**平台分节名**（`section_title`，如「数据库第三章」）
   把连续同节的块归为一册、册名即节名；没有分节时退回块标题里的**章节标记**（`第3章`/`第三部分`/`第 12 讲`）。
3. **体量兜底**：任何一册超过 300KB 时，在**块与块之间**再均衡切开（块绝不跨册拆开，册名加「（上）/（下）」或「（第N册）」）。

命名 `模块<册号>_<册名>_精读全书.md`；每册含：册名与课程信息 → 导读与全景目录（本册各章 = 各块）→
逐章正文 → 章间承前启后 → 册尾小结。**章标题优先取该块长文的 H1**，取不到才退回块标题（分集名）；
分集名不丢——写在章下那行 `> 对应块：BLK06 | 覆盖分集：P05 | 块标题（分集名）：《…》` 里供按集溯源。
同册内同名章自动补「（覆盖分集）」消歧；章内标题降一级并剥掉手写序号。缺模块长文的块**不进书**（打 gate，不落占位册）；
本轮不再产出的旧册会被清掉（教材是纯派生，可随时重建）。`articles/` 完整保留，不做任何删除。

> 教材按**块**分册，笔记按**归并后的笔记**分篇——两者粒度不同是刻意的：教材要覆盖全、便于通读，笔记要成体系、便于检索。
> **教材标题不写序号**：判定与去号规则收敛在 `src/core/heading_numbers.py` 一处，门禁（`check --deliver --require-no-numbering`）
> 与 `check --fix-numbering` 共用同一份规则。

### 2.4 任务书与目标文件对照表

| 环节 | 任务书（Agent 读取） | 目标文件（Agent 写入） | 复用/放行条件 |
| :--- | :--- | :--- | :--- |
| 阶段一 模块长文 | `articles/模块XX_*_TASK.md` | `articles/模块XX_*_精读长文.md` | 文件 ≥ 1000 字节 |
| 阶段二① 笔记归并 | `note_plan_TASK.md` | `note_plan.json` | 全部块各被认领一次（不完全合法则抢救后继续） |
| 阶段二② 笔记任务书 | `notes/笔记XX_*_TASK.md` | `notes/笔记XX_*_笔记.md` | 该篇涵盖各块的模块长文齐备即导出 |
| 阶段二③ 教材分册规划 | `textbook_plan_TASK.md` | `textbook_plan.json` | 块恰好认领一次且册名能看出内容（不合法则抢救后继续） |
| 阶段二④ 教材 | ——（纯工具整编） | `textbooks/模块<册号>_<册名>_精读全书.md` | 块长文齐备即整编（册=书、章=块；缺长文的块 gate 跳过） |

> 所有任务书均为「读完即写盘」模式：工具链只负责准备语料、渲染提示词与校验产物，**真正的语义工作全部由宿主 Agent
> （通常为子智能体）完成**。

### 2.5 交付前质检与收尾

```bash
python src/cli.py check --deliver --strict      # 笔记成色 + 渲染合规
python src/cli.py cleanup --dry-run             # 任务书回收预演（cleanup/sync 已由 cluster-* 自动执行）
python src/cli.py sync                          # 按磁盘对账回填 manifest.json
```

- **笔记成色致命项**（`套话填充 / 空壳标题 / 分集平铺标题 / 行内残缺引用 / 分集口吻`）在两套合格语料上实测均为 0，必须清零；
- **断句与结构缺件**为启发式警告项：默认按「每份 ≤ 4 处断句」提示，**结构缺件默认只报告不拦**，
  需要纳入门禁时显式加 `--require-structure`；
- **渲染致命项**为 `GitHub 告警块 / 围栏外裸字符画 / 围栏配对`；**围栏缺语言标识默认只提示不拦**，需要死守时加 `--require-lang`；
- 任务书是**临时派发物**：成品产出后由 `cleanup` 回收，**三类**各自保留编号最小的 1 份作为提示词范本（`--keep 0` 可全清）：
  块级转录任务书（`subtitles/BLKxx_*_转录任务书.md` ↔ 同名 `_逐字稿.md`）、
  模块长文任务书（`articles/模块XX_*_TASK.md` ↔ `articles/模块XX_*_精读长文.md`）、
  笔记任务书（`notes/笔记XX_*_TASK.md` ↔ `notes/笔记XX_*_笔记.md`）；`note_plan_TASK.md` 属课程级规划任务书，永不回收。

- **物理音频在全部交付物产出后自动回收**：分集源音频 `audio/Pxx_*.m4a`、块级拼接 `audio/blocks/BLKxx_*.m4a` 与劈腿切片 `audio/blocks/_parts/` 是唯一大体积的中间产物（145 集的课约 476 MB，且块音频本就是分集音频的 concat 副本），而逐字稿正文不引用音频路径。`pipeline` 收尾在**四条件全过**时自动删净：每块逐字稿齐备、模块长文齐篇、笔记已归并、教材已整编。缺任一条只跳过并打印缺什么，绝不部分删除。
  - 判定从严的原因：`queue_tracker --next-transcribe` 的派发门禁读的是 `BlockPlan.audio_ready()`，音频没了**未转录块会静默地不再派发**（既不报错也不提示）。所以判定必须盖在「逐字稿已齐」这一前置条件上，而不是「pipeline 命令返回了」。
  - 后悔药：`pipeline --keep-audio` 豁免回收。重跑同一条命令即可。
  - 记账：`manifest.json` 记 `audio_purge`（`deleted` / `bytes` / `at` / `scope`），并把 `pipeline.status` 显式写成 `purged`——否则下一轮 `_save_runtime_manifest` 会因音频已不在而把它算成 `partial`，看起来像音频物化出了问题。

> `check` **不在流水线上拦人**：它是交付前由主 Agent 手动跑的体检，只有 `--strict` 的致命项才返回非零退出码。

## 3. 断点续跑与重派

工具链以磁盘产物为唯一进度依据，重跑同一条命令即可续作：

- 模块长文、笔记归并、笔记、模块教材均按 § 2.4 表格的条件自动复用（笔记与模块教材命中成品即跳过，打印 `[cached]`）；
- 删除产物根下某个**产物**文件（如 `articles/模块03_*_精读长文.md`），即视为重新派发该环节；
- 任务书会被自动回收，因此**不要靠删除任务书来重派**。需要重导时的正确做法：
  - 笔记 / 笔记归并：`cluster-notes --force`；
  - 教材：`cluster-articles --force`（**旧册是缓存产物**：不加 `--force` 会直接跳过）；
  - 教材分册规划：编辑 `textbook_plan.json` 后重跑 `cluster-articles`；
  - 模块长文：`pipeline --force`，或直接删除该块的 `articles/模块XX_*_精读长文.md` 后再跑；
  - 块标题：修改 `block_titles.json` 后重跑 `pipeline`（已锁定块不会被重排）；
- 用 `queue_tracker.py --next-module 5` 查看阶段一待办块队列，`--summary` 获取单行状态；
  多课程并存时加 `--pattern` / `--dir` / `--base-dir`；
- 若 `manifest.json` 与实际产物不一致（例如 Agent 直接写盘后清单未回填），执行 `python src/cli.py sync` 按磁盘对账
  （`cluster-*` 收尾已自动执行一次）。

> **归并卡住时怎么办**：`note_plan.json` 不合法**不会**让命令失败退出——工具会当场丢弃引用不存在的块、
> 先到先得处理重复认领、把没人认领的块各补成一篇兜底笔记，并把做了什么**逐条打印出来**
> （重复认领会点明「哪一块、被第几册重复认领、保留的是第几册」），命令正常结束。
> 修好归并文件后重跑一次即可换成真归并；盘上那份**永远不会被工具改写**。

> **处理范围**：流水线处理的是**当前稿件被选中的那批分 P**（即 `parts.json` 的内容）——`--range 9-87` 得到的就是
> 9..87 共 79 集，集号保持原样、不重排。`cluster-notes` / `cluster-articles` 的集号基准**一律取工作区 `parts.json`**，
> 不用在线解析出来的课程全集（在线解析只用于首次建工作区）；课程标题同理，取 manifest → 工作区目录名，**离线也能跑**。
