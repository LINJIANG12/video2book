# `references/` 是什么

**这是 Agent Skill 的「渐进式披露层」。**

Agent Skills 规范的约定是：`SKILL.md` 只放**每次执行都必须知道的**主路径（短、稳定、可直接照做）；
而**只在特定情形才需要的**细则，拆成若干文件放在 `references/` 下，由 agent 按需读取。

这样做的收益是**上下文预算**：一份完整的运行手册接近 1000 行，但一次典型任务只会用到其中一两份文件。
全部塞进 `SKILL.md` 会让每次调用都背上全部体量，还会稀释主路径的注意力。

`SKILL.md` 第 6 节是这些文件的索引（"什么情况读哪份"）。本文件解释这一层的**结构**与**维护规矩**。

## 文件分工

| 文件 | 回答的问题 | 什么时候读 |
| :--- | :--- | :--- |
| [`workflow.md`](workflow.md) | 阶段一/二**怎么做**：逐步细则、派发与回报协议、验收返修、断点续跑 | 执行任务时（主路径之外的分支） |
| [`runtime.md`](runtime.md) | 跑起来**需要什么**：三层依赖与缺失处置、两条听音通道与分页契约、凭证获取与安全 | 环境缺东西、或要拿凭证时 |
| [`cli-cookbook.md`](cli-cookbook.md) | 命令**怎么写**：八个场景的完整命令、参数全表、退出码 | 拼命令时 |
| [`delivery_matrix.md`](delivery_matrix.md) | 产物**长什么样**：长文类型矩阵、工作区目录树、排版与渲染兼容 | 写产物 / 改产物格式时 |
| [`non-video-works.md`](non-video-works.md) | 非视频作品（抖音图文/图集）怎么处置 | 只在遇到这类输入时 |
| [`install.md`](install.md) | **装到哪**：安装单元、平台安装位对照、手动安装三法 | 部署技能时 |
| [`host-tools/`](host-tools/) | **工具名叫什么**：行动语义 → 各平台私有工具名 | 需要把行动语义落成具体工具调用时 |

## 两条维护规矩

1. **`SKILL.md` 与 `references/` 不许说两遍。**
   同一件事只能有一个真源：要么在主路径里（每次都需要的），要么在这一层（按需的）。
   发现两处都在讲同一件事，就删掉较薄的那一份，改成指向另一份的链接
   （例：`install.md` 的前置依赖只列三项，完整表格只在 `runtime.md` §1）。

2. **`references/` 里的文件是「按需读取」的，所以每个文件都要能独立读懂。**
   不要写"见上文"——上文不在这个文件里。跨文件引用一律写成显式链接。

## 新增一份文件的判断标准

先问：**这件事是不是"只在特定情形才需要"？** 如果每次执行都要知道，它属于 `SKILL.md`。
如果只在某类输入、某个阶段、某个平台才需要，它才属于这里。

不要为了"看起来完整"而新增占位文件——一个写满"待确认"的空壳会让 agent 误以为有据可依。
