# 非视频作品：识别与处置

> **适用对象**：抖音博主主页里的**图文作品**（图集 note）——即一组图片配 BGM 的作品，
> 没有讲师口播。本文件说明如何识别它们，以及工具链为什么、以何种方式把它们排除在
> 听音与长文生成之外。

---

## 1. 什么是非视频作品

抖音博主主页混着两类作品：

| 形态 | API 特征 | 音频内容 | 能否写教材长文 |
| :--- | :--- | :--- | :--- |
| **常规视频** | `images` 为空 | 讲师口播 | ✅ 可以 |
| **非视频作品（图文/图集 note）** | `images` 非空（一组图片） | 图片卡片 + BGM，**无任何人声** | ❌ 不能（无音频事实） |

非视频作品的分享页路径是 `/share/note/{aweme_id}/`（视频是 `/share/video/{aweme_id}/`），
但**两条路径最终都经同一个归一化函数处理**，所以判定口径只需在一处定义。

---

## 2. 识别口径（唯一信号：API 的 `images` 字段）

**判定是正向的**：`images` 非空 → `image_album`（图文）；否则 → `video`。

```python
# src/core/ingestion/dyaudio/share_parser.py :: parse_single_aweme()
media_kind = "image_album" if images else "video"
```

该值随 `parts` 一路传到下游，落在两个地方：

| 位置 | 形态 | 用途 |
| :--- | :--- | :--- |
| `parts.json` 的 `media_kind` | `"video"` / `"image_album"` | 跨命令的**权威标记**，所有命令都读它 |
| `manifest.json` 的 `non_video_episodes` | 条目列表（含 `skip_reason: "non_video"`） | 本次流水线的**跳过记录** |

### ⚠️ 两个不能用的信号

**① 不能用 `video_urls` 反推。** 抖音的图文作品常带一段**合成预览视频**（`video.play_addr` 有值），
用「有没有视频地址」来判会把图集**漏判成视频**。必须正向看 `images`。

**② 不能用 `duration` 判。** 图文作品的分享页**照样带** `video.duration`（实测某集 = 19 秒），
与常规视频完全无法区分。

### 供排查参考的体积分布（**不作为判定依据**）

某摄影博主 216 集实测，音频体积呈三峰：

| 形态 | 典型体积 |
| :--- | :--- |
| 无口播（图片卡片 + BGM） | **78–148 KB** |
| 有口播短教学 | 200 KB – 1 MB |
| 长合集 | 37 – 51 MB |

体积只能用来**事后怀疑**某一集是不是图文作品，不能作为自动判定依据——
`media_kind` 才是权威信号（`duration` / 体积都会误判）。

> 已知的边界情形：少数集既不是图文作品、也没有口播（纯演示/纯 BGM 视频）。
> 本工具**不尝试**识别这类情形——它需要语义判断，工具层做不到。
> 这类集仍会照常派发，由撰写环节按红线 2 如实处理（拿不到内容就如实说明，不得编造）。

---

## 3. 处置规则

非视频作品在流水线里被**全程排除**，且计入 **`skipped`（跳过）而非 `failed`（失败）**：

| 环节 | 对非视频作品的行为 |
| :--- | :--- |
| 结构解析 | ✅ 照常进入 `parts.json`（**拓扑完整性**：集号基准、`--range` 位置索引都需要它） |
| 音频下载 | ⛔ **不下载**（没有可用音轨，下来只有 BGM） |
| 阶段一 A：块级转录 | ⛔ **不进块、不派发转录任务**（计划生成前已从待规划集里预筛掉，块时间表里不会出现它们的集号） |
| 阶段一 B：模块长文任务书派发 | ⛔ **不派发** |
| 阶段二：模块规划 / 笔记归并 | ⛔ **不参与**（`scope_parts` 已过滤） |
| 教材整编 | ⛔ **不参与**（`cluster-articles` 已过滤，避免空壳章节） |
| 账本对账 | ✅ 计入 `manifest.skipped_pages` / `non_video_episodes`，`state_sync` 自动从有效总数里扣减 |

### 为什么必须排除，而不是「先派发了让 Agent 自己跳过」

两个理由，任一条都足以定案：

1. **红线 2（逐字稿事实保真）**：所有长文必须建立在**块级逐字稿**之上（块级转录链路的产物）。
   图文作品没有口播 → 没有事实来源 → 写出来的任何正文都是编造。明确不派发比「派发了但拿不到内容」更安全——后者会诱导撰写环节硬凑内容。
2. **门禁语义**：不排除的话，阶段二的音频就绪校验会把图文作品当成「音频缺失」而**误报故障**，
   并且 `pipeline_completed` 会因为「永远凑不齐这几集的长文」而**永远是 false**。

## 4. 怎么回查

```bash
# 看工作区里哪些集是图文作品（权威标记）
python -c "import json;d=json.load(open('output/<task>/parts.json',encoding='utf-8'));print([p['page'] for p in d if p.get('media_kind')=='image_album'])"

# 看本次流水线跳过了哪些集、为什么跳过
python -c "import json;m=json.load(open('output/<task>/manifest.json',encoding='utf-8'));print(m.get('non_video_episodes'))"
```

流水线运行时也会**显式打印**清单（不静默跳过）：

```text
[*] 检出 14 集非视频作品（图文作品，无口播）：不下载音频、不派发文章任务书
    - P04 [image_album] 记录本身就是拍照的意义 #风光摄影 ...
```

## 5. 兼容性

- **旧工作区**（B 站 / YouTube / 本地媒体，以及本特性之前建立的抖音工作区）：
  `parts.json` 里没有 `media_kind` → 一律按 `video` 处理 → **行为与改动前完全一致**。
- **`manifest.json`** 的 `non_video_episodes` 是新增字段，旧工作区没有；
  所有读取方都用 `.get(...)` 兜底为空列表，不会报错。
- 集号与顺序不受影响：非视频作品**保留在 `parts.json` 里**，`--range` 的位置索引照旧。
