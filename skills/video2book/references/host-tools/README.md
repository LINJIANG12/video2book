# 工具映射层：行动语义 → 各平台工具名

## 为什么有这一层

技能正文只描述**行动语义**（"读文件""写盘""派子智能体"……），**不写死任何平台的私有工具名**。
这样同一份 `SKILL.md` 才能装到 Claude Code、Codex、OpenCode 等支持 Agent Skills 规范的平台而不失效；
平台差异全部收在本目录，一个平台一个文件。

> **最高原则（所有平台通用）**
> **当本目录的表格与你实际可用的工具列表冲突时，以你的工具列表为准。**
> 本目录是提示，不是事实来源——各平台的工具集会随版本变化。请先列出你自己的工具，再按行动语义就近匹配。

## 行动语义基线（技能正文里会出现的全部动词）

| 行动语义 | 含义 | 备注 |
| :--- | :--- | :--- |
| **读文件** | 打开一个文件并获取内容 | 若目标是音频/视频切片，必须用**能直接感知媒体内容**的那件工具（多模态读文件），普通文本读不行 |
| **写盘 / 创建文件** | 新建文件并写入内容 | 落盘产物 |
| **改文件** | 就地编辑已有文件 | 返修时 |
| **执行 shell / CLI 命令** | 运行 `python src/cli.py …`、`python scripts/…` | |
| **检索文件内容 / 按名找文件** | 在仓库里搜索 | |
| **派发子智能体** | 派生独立上下文的子 agent 完成一件独立的事 | 本技能阶段一的核心机制；**部分平台需显式开启多智能体特性** |
| **等待 / 回收子智能体** | 等子智能体完成并取回结论 | |
| **待办清单** | 记录多步进度 | 可选 |
| **取网页** | 抓取 URL 内容 | 阶段一不需要，仅少数场景 |
| **原生听音** | 用 MCP 工具取到音频切片，再用"读文件"能力聆听 | 见下 |

**两条通道是 MCP 工具名，跨平台一致**（按「能直写落盘者优先」排序）：

- `read_media` —— **优先推荐**（外部模型代读；服务本体在配套仓库 `omni-media/` 的**单一包**里，
  挂载注册名 `omni-media-ext`、`--mode ext`，支持 `output_file` 原子直写磁盘、0 Token 进上下文，防摘要冒充逐字稿）
- `read_audio` —— 工具列表里没有 `read_media` 时使用（宿主原生听音，零凭证；**同一个包**，
  挂载注册名 `omni-media`、`--mode native`；默认位置 `<容器根>/omni-media/`）

判断依据永远是**你自己工具列表里出现了哪一个**，不要猜。

**除末行兜底外，上表只列有实据的平台。** 没有实据的平台不留占位文件——一个写满"待确认"的空壳会让人
以为技能支持它，装上却可能失效。缺依据时，宁可让你按下面的方法现场判断。

## 本平台不在上表怎么办

1. 列出**你自己**当前可用的工具；
2. 按上面的「行动语义基线」逐条就近匹配（拿不准就先用自然语言问本平台的 agent）；
3. **不要**把一个平台的工具名照搬到另一个平台（例如 Claude Code 的 `Read` / `Bash` 在别的平台通常不存在）；
4. 若匹配结果与技能正文的表述冲突，**以你的对照为准，不要去改 `SKILL.md` 写死工具名**——
   那会让技能在其它平台失效；
5. 这份对照**是给你自己用的**，不必往本目录里加文件。真要新增平台支持：先拿到实据（官方文档 /
   官方清单 schema / 实测工具列表），再补 `<平台>.md`，并同步 `references/install.md`、自检的
   `HOST_TARGETS`，同时把该平台名从自检的 `_UNVERIFIED_TRACE_NAMES` 里移除（漏这步自检会红）。
